## 1. 현재 결론

현재 프로젝트는 실행 가능한 앱 본체, 루트 진입점, viewer 진입점, 매니페스트, 프로젝트 매니페스트, 복구 리포트를 갖춘 상태다. 다만 전체 개발 기획서는 하나의 완성 문서로 통합되어 있지 않고, 여러 파일과 대화 맥락에 분산되어 있다.

따라서 v4.8.31 기준 최우선 과제는 기능 추가가 아니라 다음 세 가지다.

1. 기준 문서 통합
2. 진입점/매니페스트/앱 본체 정합성 유지
3. v4.8.32에서 모바일 메뉴 폭 미세 조정만 수행

## 4. 핵심 설계 기준

### 4-1. 화면 구조

- 상단: 프로젝트명/현재 탐험 안내
- 중앙: 수족관 메인 화면
- 상단 보조: 5존 선택, 낮물/밤물 선택
- 하단: 탐험 / 도감 / 반짝 / 카메라
- 시트: 도감, 반짝, 카메라 안내
- 모달: 물고기 상세 정보

### 4-2. 존 기준

공식 명칭은 다음으로 고정한다.

1. 웃물
2. 여울
3. 잔여울
4. 깊물
5. 물모이

과거 표현인 상류, 평여울, 소, 합수부, 두물머리는 내부 설명에는 쓸 수 있으나, 버튼·상태칩·문서 대표 명칭은 위 5개로 통일한다.

### 4-3. 개발 원칙

- 앱 본체는 `app_assets/index.html`을 기준으로 한다.
- 루트와 viewer는 앱 본체로 보내는 얇은 진입점으로 유지한다.
- 단일 대형 HTML에 기능을 무리하게 덧붙이지 않는다.
- 기능 추가 전 항상 백업 브랜치를 만든다.
- 패치는 CSS/문구/자산/함수 단위로 분리한다.
- 한글 주석과 한글 리마크를 유지한다.
- JOHN CHOI 표기를 유지한다.

## 5. 현재 위험 요소

### 위험 1. 전체 개발 기획서 분산

현재 기준은 `manifest.json`, `project-manifest.json`, 복구 리포트, HTML 내부 주석, 대화 메모, 업로드 문서에 흩어져 있다. 이 상태에서는 다음 작업자가 기준을 혼동할 수 있다.

대응: 본 문서를 기준 통합 문서로 사용하고, 이후 변경 때마다 업데이트한다.

### 위험 2. 앱 본체 버전명 불일치

매니페스트는 v4.8.31로 갱신됐지만, 앱 본체 HTML title은 아직 `Pongdang4 v4.8.30 Phone Zone Label Fit Test`로 남아 있다.

대응: v4.8.32에서 실제 화면 검증 후 title만 `Pongdang4 v4.8.32 Phone Menu Fit Recovery`로 갱신한다. 앱 엔진은 건드리지 않는다.

### 위험 3. 최신본과 과거 안정본 기능 차이

과거 `r21.3 render safety` 계열에는 리포트 공유, 안정화 복구 함수, 결과 리포트 닫기, 카메라 기록 관련 함수가 포함되어 있었다. 현재 저장소 최신본에 같은 기능이 모두 살아 있는지는 전수 검증이 필요하다.

대응: 기능 이식은 금지하고, 먼저 존재 여부만 체크한다.

### 위험 4. 22종 자산 기준과 현재 앱 등록 종 불일치 가능성

별도 자산 기준서에는 곤지암천 22종 실사 이미지 제작 기준이 있으나, 현재 앱에 22종이 모두 등록되어 있는지는 확인되지 않았다.

대응: v4.8.33에서 어종 데이터 테이블을 별도 문서화한다.

### 위험 5. 카메라 기능 실기기 권한 검증 미완료

카메라 UI와 스타일은 존재하지만, Android Chrome, iOS Safari, Netlify 배포 주소에서 권한 동작을 확인해야 한다.

대응: v4.8.32 이후 카메라 권한 체크리스트 작성.
